# ADR 0006: Invites, per-process agent identity, CTF.md and task cooperation

Status: accepted (0.6.0)

## Context

Feedback from CTF Lviv 2026 (owner and eight agent sessions) showed that most lost
time came from setup and identity rather than from the coordination core:

- the first agent was hard to connect; nicknames were generated by ad-hoc scripts;
- several sessions shared one access file, so leases, flags and renames collided;
- the MCP bridge read its access file once, so a port/URL change required restarts,
  and errors did not say which server was unreachable or that it was the wrong app;
- the rules ("never unlock platform hints") existed only as a broadcast;
- people wanted to help with a task without taking it, and to "take all forensics";
- flags were not linked to tasks, and verifying one required writing evidence.

## Decision

1. **Invites.** A lead creates an expiring, use-limited invite (`invites` table, only
   its SHA-256 stored). `POST /api/v1/join` with the invite creates a human with the
   invite's role and, by default, their first agent. It cannot do anything else.
2. **Enrollment without owner tokens.** Non-owner workers/coordinators may enroll
   `kind=agent, role=worker` actors for their own human (agents for their owner).
   Owners keep full enrollment. An agent created by a human belongs to that human.
3. **Readable names.** Agent names are `<Human>-<Callsign>_<4 chars>`; a requested
   name is prefixed with the owner's first word. Uniqueness rules are unchanged.
4. **One process, one identity.** The MCP bridge treats a human (or redeemed invite)
   credential as a seed and takes a free pooled agent or enrolls one; an agent file
   already held by another live process yields a sibling. Locks are advisory OS file
   locks keyed by actor id under `$TEAM_SYNC_STATE_DIR` and vanish with the process.
   `TEAM_SYNC_IDENTITY=direct` preserves the previous behaviour.
5. **Lazy, reloadable bridge.** Identity is resolved on first use and re-resolved
   when the access file changes or after 401/transport errors. `/health` reports
   `service: ctf-team-sync`, so a different application on the port is reported as
   `wrong_server`. MCP logging goes to stderr at WARNING.
6. **CTF.md.** `projects.briefing` (editable, versioned like other project fields) +
   project rules + a fixed, non-editable mandatory section are rendered as CTF.md,
   returned on enrollment/join and via `/ctf.md`, `/briefing` and MCP `get_briefing`.
7. **Cooperation.** `task_participants` records people/agents working on a task
   without touching its single lease (`task.join`, `task.leave`, `task.join_many` by
   category or challenge). Leases, versions and the claim rules are unchanged.
8. **Flags and findings by task.** `flags.task_id` (challenge derived from the task);
   findings with `task_id` inherit the task's challenge. `flag.verify` evidence is
   optional; an empty one records who decided.
9. **Agent ergonomics.** Errors carry machine fields (`current_version`,
   `existing_id`); duplicate challenge/unfinished task titles return 409 unless
   `allow_duplicate`; search requires every word and also matches the linked
   challenge/task title; journal `query` also matches resource titles; context
   sections never return empty `items` with `total > 0` and report `omitted`/`more`;
   signed URL parameters are redacted in excerpts (full resources keep them); own
   broadcasts are no longer listed in the sender's inbox/attention.

## Compatibility

Migration `c41d7e2f9a10` only adds a column, a nullable FK column and two tables.
Old command payloads remain valid; new optional fields are dropped from idempotency
fingerprints when they have default values. Behavioural changes visible to old
clients: duplicate titles now return 409, enrolling an unnamed agent yields a
prefixed callsign instead of `Nova/Atlas`, and an owner-created agent gets
`owner_id` set to the creating human.
