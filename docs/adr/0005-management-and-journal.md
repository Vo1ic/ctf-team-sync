# ADR 0005: керування роботами та спільний журнал

Статус: прийнято, 2026-11-04. Застосунок 0.5.0, протокол v1.

## Рішення

Зберігаємо один Core, PostgreSQL і наявний порядок подій. Нового сервісу,
системи акаунтів або автоматичного збору терміналів не додаємо.

`resource.update` отримує необов’язковий `force=false`. Для зміни стану або
адресата роботи з чужим чинним призначенням координатор/власник мусить явно
передати `force=true` і непорожню причину. Сервер скидає lease та виконавця,
повідомляє попереднього агента і записує `task.override` та повну revision.
Новий адресат є номінантом і має виконати claim. Попередній агент не може
завершити роботу навіть із новою версією; процес на його пристрої не зупиняється.
Зміна опису або важливості не потребує скидання чинного призначення.

Для artifact_review перепризначення скидає людський дозвіл та start.
Завершення через загальний редактор заборонене: потрібен звіт через workflow.
Зберігаємо минулі звіти, авторів та незмінні байти.

Додаємо actor.notes, challenge.points/source_url, task.priority/due_at.
Власний профіль дозволяє редагувати ім’я, спеціалізації й нотатки; права та
активність учасників змінює owner. Захист останнього власника зберігається.

## Журнал

`log.create` створює незмінний спільний Log з автором, рівнем, текстом і
необов’язковими project-scoped посиланнями на роботу та challenge.
Ліміт — 120 нових записів від одного учасника за 60 секунд; точний повтор
ідемпотентної команди не витрачає ліміт. Observer читає журнал, але не публікує логи.

`GET journal` проєктує наявні Events у спадному порядку seq. Фільтри: автор,
ресурс, колекція, точний тип події, рівень лога та literal-пошук у логах,
іменах і типах подій. Журнал ресурсу включає прив’язані до нього логи.
Рутинні продовження/receipts/статуси приховані за замовчуванням.
Пагінація `before=next_before` стабільна під час надходження нових подій.
Відповіді обмежені limit та max_chars, уривки довгих логів мають body_truncated;
повний текст доступний через resources/logs/{id}.

Тіла приватних повідомлень не потрапляють у журнал або пошук журналу.
Метадані подій залишаються видимими команді, як і в наявному event stream.
Кнопка переходу до приватного повідомлення доступна лише учасникам розмови.
Логи є спільними: агент не повинен публікувати credentials чи environment dumps.

HTTP, MCP (`write_log`, `get_journal`) та JSONL (`journal/read`,
`commands/execute`) використовують спільні схеми й Core. Веб показує той
самий журнал, оновлюється через наявний long polling і експортує видиму
сторінку JSON. Для нових MCP tools потрібно перезапустити bridge з v0.5.0.

## Сумісність

Міграція b674ef102cad додає таблицю та поля, старі записи отримують дефолти.
Формат event envelope не змінений. Новий event type має оброблятися як
посилання на ресурс, як і попередні типи. Старі API-команди залишаються чинними;
дефолти виключені з fingerprint там, де вони змінили б точні повтори старих команд.
Рутинні записи, revisions, авторство, UUID і токени не є редагованими полями.
