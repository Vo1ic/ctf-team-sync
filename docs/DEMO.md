# Демонстрація командної роботи

Демо створює окремий CTF **DEMO · Nightshift CTF** через звичайний HTTP API.
Це синтетичні дані та імітація дій агентів; моделі не запускаються.
Існуючі проєкти не змінюються. Всі команди потрапляють у справжній журнал подій.

## Наповнити сервер

Із кореня репозиторію, після запуску Compose:

```sh
uv run python scripts/demo.py seed --env-file .env
```

Для іншого сервера можна передати `--url`. Ключ ініціалізації читається з
environment або вибраного env-файла. Команда виводить URL, UUID і шлях до
приватного файла доступу; сам токен у термінал не виводиться.
Кожен запуск створює новий демонстраційний CTF.

Початкові дані:

- 11 identities: капітан, агент-координатор, аналітики, різні CLI/IDE-агенти,
  спостерігач і агент із відкликаним доступом. Назви ОС/клієнтів імітовані.
- 5 CTF-завдань: Web, Crypto, Forensics, Reverse, Misc.
- 13 робіт: 5 завершених, 5 із чинним призначенням і 3 доступні.
- 11 знахідок: спостереження, гіпотези, результати й невдалі спроби.
- 6 флагів: неперевірені, підтверджені, відхилений і прострочений.
- Історія повторної перевірки та приклади accepted/rejected/unknown відправлень.
  Звіт про відправлення імітований, реальна платформа не викликається.
- 6 файлів із SHA-256 та посиланнями з доказів у знахідках.
- Broadcast і приватні повідомлення; власний inbox капітана має стани
  «Нове», «Отримано», «Опрацьовано». Приватний обмін інших identities капітану
  не показується.

Credentials, manifest і короткий підсумок записуються з приватними правами в
gitignored `.team-sync/demo/<project-id>/`. Owner-доступ — в `access.json`,
окремі identities — в `identities.json`. Ці файли не слід публікувати.

## Відкрити підключений браузер

Звичайний варіант: відкрити виданий URL і скопіювати `token` з приватного
`access.json` у форму. UUID уже буде підставлено з URL; токена в URL немає.

Якщо встановлені dev-залежності Node і Chromium Playwright, можна відкрити
окреме вікно з уже виконаним підключенням:

```sh
node scripts/demo-preview.mjs --access-file .team-sync/demo/<project-id>/access.json
```

Це окремий браузерний контекст; особистий профіль браузера не змінюється.
Потрібна графічна сесія. Для screenshot без графічного вікна:

```sh
node scripts/demo-preview.mjs \
  --access-file .team-sync/demo/<project-id>/access.json \
  --headless --screenshot .team-sync/demo/<project-id>/overview.png
```

Підключення зберігається у приватному cookie на 7 днів. Refresh відновлює CTF
без повторного введення токена; «Від’єднатися» прибирає браузерний доступ.

## Подивитися зміни в процесі

Відкрити **Роботи**, **Огляд**, **Флаги** або **Повідомлення**, потім запустити:

```sh
uv run python scripts/demo.py play \
  --access-file .team-sync/demo/<project-id>/access.json \
  --episodes 4 --interval 20
```

Кожні 20 секунд відбувається наступний крок: створення роботи → claim агентом →
публікація файла і знахідки → неперевірений флаг → підтвердження координатором →
завершення роботи та окремий звіт про відправлення. Чотири епізоди тривають
приблизно 8 хвилин. Вебсторінка отримує зміни через наявний event transport
без перезавантаження.

Відтворення скінченне, зупиняється через Ctrl+C і залишає створені дані.
Повторний запуск додає нові епізоди з унікальними флагами. Скрипт перевіряє
демонстраційний marker проєкту перед відтворенням. Початкові running-роботи мають
lease на годину; після спливу UI показує можливість взяти їх повторно.

Для читання без можливості змін виберіть у `identities.json` identity
`observer`: використайте її `token` і той самий UUID проєкту в іншій вкладці.

Це демонстрація поведінки інтерфейсу. Реальні модельні учасники перевірялися
окремо: [живе приймання Claude Code й Codex](LIVE-ACCEPTANCE.md).
