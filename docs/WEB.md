# Вебінтерфейс

Відкрийте адресу свого Team Sync сервера. У локальному Compose це
`http://localhost:8000/`. Вебчастина й API працюють з одного origin; додатковий
frontend-сервер або Node у production не потрібні.

## Перший CTF

1. Виберіть **Ініціалізувати проєкт**.
2. Вкажіть назву, своє ім’я, формат, наявність флагів і контекст змагання.
3. Введіть ключ ініціалізації, який налаштовано на сервері.
4. Збережіть виданий owner token і project ID. Сервер повторно не показує токен.
5. Додайте завдання та конкретні роботи. У **Команді** видайте окремий доступ
   кожному учаснику й незалежному агенту.

Для вже створеного проєкту достатньо project ID та особистого token.
Токен зберігається тільки в пам’яті відкритої сторінки. Після перезавантаження
або закриття вкладки його потрібно ввести знову. Останній project ID запам’ятовується.

Щоб оглянути заповнений простір із прикладами всіх розділів, використайте
[демонстраційний CTF та відтворення командної роботи](DEMO.md).

Після видачі доступу агенту можна зберегти MCP-конфігурацію. Файл містить його
особистий токен. У `args` потрібно замінити `/path/to/team-sync` на шлях до
checkout на пристрої учасника; синтаксис обгортки залежить від конкретного host.

## Щоденна робота

- **Огляд:** роботи, знахідки, підтверджені флаги та останні події.
- **Завдання CTF:** зовнішні завдання змагання, категорії та пов’язані роботи.
- **Роботи:** дошка доступних, виконуваних і завершених робіт. Виконавець бере
  роботу на себе, поновлює призначення та завершує з описом результату.
- **Знахідки:** спостереження, гіпотези, результати й невдалі спроби, з доказами.
- **Флаги:** кандидати та історія перевірок. Owner/coordinator записує висновок.
  Результат відправлення записується окремо; UI не надсилає флаг на платформу.
- **Повідомлення:** особисті вхідні й broadcast. Читання не підтверджує обробку:
  натисніть **Отримано** або **Опрацьовано** явно.
- **Файли:** публікація незмінних артефактів і завантаження з перевіркою SHA-256.
  Кнопка копіювання дає посилання `artifact:<UUID>` для поля доказів у знахідці;
  відомі посилання на артефакти стають кнопками завантаження в картці знахідки.
- **Команда:** identities, спеціалізації, roles та відкликання доступу. Позначка
  «Доступ активний» не означає, що модель зараз виконується чи отримала повідомлення.

Observer читає спільний стан і підтверджує власні повідомлення. Недоступні ролі
дії приховані, а сервер незалежно перевіряє авторизацію кожної операції.

## Синхронізація і помилки

Зміни від інших браузерів та MCP-клієнтів з’являються автоматично. При втраті
зв’язку sidebar показує стан перепідключення; поточні дані залишаються на екрані.
Після відновлення зчитуються пропущені події. Курсор належить поточній сторінці;
нове підключення спочатку завантажує актуальні колекції та останні події.

Якщо відповідь на команду втрачена, форма зберігає початкові значення й пропонує
**Повторити запит**. Використовується той самий ключ, тому повтор не створює дубль.
Закриття форми прибирає її стан; перед створенням нової операції перевірте дані.
Створення CTF і видача token мають інші гарантії: при невідомому результаті їх
не можна автоматично повторити й отримати попередній секрет. Якщо відповідь із
секретом отримано, збій подальшого оновлення екрана не приховує виданий токен.

Конфлікт версії означає, що стан уже змінився; потрібно відкрити свіжий запис і
повторити дію. Lease перевіряється сервером, а UI оновлює доступність після строку
дії. Відкликання доступу завершує браузерне підключення та прибирає спільні дані.

Для перевірки цілісності файлів браузер використовує Web Crypto. На віддаленому
сервері потрібен HTTPS; localhost також підтримується.
[Обмеження secure context у Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/digest).

## Перевірки

`npm run test:web` перевіряє транспорт, ідемпотентні повтори, пагінацію, скасування
запитів і контрольні суми. `npm run test:e2e` запускає Chromium проти ізольованого
PostgreSQL-backed сервера: дві сесії, роботи, флаги, receipts, credentials,
втрачені відповіді, відкликання доступу та мобільний viewport.

Автоматичні тести ще не замінюють перевірку на фізичних пристроях команди та в
її конкретних CLI/IDE. Є [checkpoint adapters](ADAPTERS.md) і окремий
[живий прогін Claude Code та Codex-субагентів](LIVE-ACCEPTANCE.md).

Для розробки використовуйте `docker compose -f compose.yaml -f compose.dev.yaml up --build -d`.
Python-код перезавантажується автоматично; зміни HTML/CSS/JS видно після refresh
сторінки. Постійні volumes використовуються ті самі, що у звичайному Compose.
