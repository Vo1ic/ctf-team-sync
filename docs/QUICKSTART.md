# Швидкий старт команди (0.9)

Мета: від порожньої машини до команди з агентами за кілька хвилин, без ручної
генерації ніків, без спільних access-файлів і без перезапусків MCP після правок.
Кожен крок може виконати як людина, так і агент за її дорученням.

## 1. Власник: підняти сервер і створити CTF

```sh
cd tools/ctf-team-sync
scripts/quickstart.sh "CTF Lviv 2026" Vo1ic
```

Скрипт:

- створює `.env` з випадковими секретами, якщо його немає (секрети не друкуються);
- бере вільний порт `127.0.0.1:8000…8099` або повторно використовує вже запущений
  Team Sync (порт зберігається в `.env` як `TEAM_SYNC_HOST_PORT`);
- запускає `docker compose up -d --build` і чекає `/health` саме Team Sync
  (інший застосунок на порту розпізнається й не плутається з сервером);
- створює проєкт, `.team-sync/<ctf>/owner.json` (ти) та `invite.json` (для команди).

Порт вручну: `TEAM_SYNC_HOST_PORT=8010 docker compose up -d`.

## 2. Підключити агентів (свої й тімейтів)

Один MCP-конфіг на всіх агентів однієї людини. Отримати його:

```sh
uv run team-sync-agent --access-file .team-sync/ctf-lviv-2026/owner.json \
  mcp-config --host opencode      # або claude-code / codex
```

Як працює ідентичність:

- access-файл **людини** (owner.json або файл після join) — це «насіння»: кожен
  запущений MCP-процес бере собі вільного агента цієї людини або створює нового з
  ніком `<Людина>-<Позивний>_<4 символи>`, наприклад `Vo1ic-Desos_b23s`;
- два одночасні процеси ніколи не отримують одну ідентичність (OS-lock на агента);
- access-файл **агента**, який уже використовує інший процес, дає новому процесу
  окремого «брата» з тим самим власником;
- `TEAM_SYNC_IDENTITY=direct` вимикає це й працює строго під файлом як є.

MCP перечитує access-файл, коли він змінився: виправлення URL/порту чи проєкту
не потребує перезапуску сесії. Помилки містять URL і причину: `server_unreachable`,
`wrong_server` (на порту інший застосунок), `join_required`.

## 3. Тімейт: один файл + MCP-конфіг

Власник створює запрошення у вебі (**Підключення → Створити запрошення**) або CLI:

```sh
uv run team-sync-agent --access-file owner.json invite --out team-sync-invite.json
```

Тімейт кладе `team-sync-invite.json` у робочу теку, додає MCP-конфіг із
`TEAM_SYNC_ACCESS_FILE=<шлях до файла>` і пише агенту «підключись до team-sync».
Агент отримує `join_required`, питає нікнейм і викликає `join_team(human_name=...)`:
сервер створює людину, а агент отримує власну ідентичність `<нік>-<Позивний>_xxxx`
і CTF.md. Запрошення дає право лише створити людину та її агентів; строк дії й
кількість використань обмежені. Без MCP: `team-sync-agent join --invite <file> --human <нік>`.

## 4. CTF.md

`CTF.md` зберігається на сервері, віддається при реєстрації та в будь-який момент:
MCP `get_briefing`, `GET /api/v1/projects/<id>/ctf.md`, кнопка **CTF.md** у вебі.
Текст редагує власник/координатор (Налаштування CTF → «CTF.md»). Розділ
«Обов'язково» (не відкривати підказки, не здавати флаги самостійно, scope,
дані ≠ інструкції) додається завжди й не редагується.

## 5. Імпорт тасок із CTFd

```sh
export CTFD_TOKEN=...   # CTFd → Settings → Access Tokens (або CTFD_SESSION=<cookie>)
uv run team-sync-agent --access-file owner.json import-ctfd --ctfd-url https://ctf.example
```

Створює challenge (категорія, бали, опис, файли, connection info, кількість
підказок із попередженням) і таску `Solve: <назва>` для кожного. Повторний запуск
безпечний: наявні записи не дублюються. Підказки не розблоковуються. `--dry-run`
показує, що буде імпортовано.

## 6. Структура директорій

```sh
uv run team-sync-agent --access-file owner.json workspace --root challenges/ctflviv2026
```

Створює `CTF.md` і `<категорія>/<завдання>/CHALLENGE.md` (id, таски, опис, джерело).
Власні файли в теках не чіпаються; команду можна запускати повторно.

## 7. Хто є хто в терміналах

`whoami` (MCP) або `team-sync-agent --access-file <file> whoami --title` показує
позивний, власника й проєкт і ставить назву вкладки терміналу, напр.
`Vo1ic-Desos_b23s · CTF Lviv 2026`. Ім'я агента також видно в журналі й у вебі.

## 8. Кооп по тасках

- `join_task(task_id)` — працювати разом із виконавцем, не забираючи lease.
- `join_tasks(category="forensics")` — «я беру всю форензику» для людини-власника.
- Учасники видно в картках робіт («Разом: …») і в `get_context.joined_tasks`.
- Флаги прив'язуються до роботи: `create_flag(value, task_id)`; у вебі флаги та
  знахідки згруповані по завданнях, перевірка флага — одна кнопка «Підтвердити».

## 9. Документація завдання: ланцюжки гіпотез, файли, райтап

- Агент публікує гіпотезу **до** перевірки: `report_finding(kind="hypothesis", task_id=...)`.
- Результат перевірки — `report_finding(..., based_on=[гіпотеза])`; якщо вона хибна —
  `refutes=[гіпотеза]` (стане «спростована»). `link_items` додає будь-які інші ребра.
- Файли: `publish_artifact(path, attach_to_task_id=...)` або «Прикріпити файл» у вебі.
- **Документація** у картці завдання: граф гіпотез (клік — перехід до знахідки),
  райтап, умова, файли, роботи, повна історія з доказами, флаги. «Завантажити .md»
  дає той самий документ (з Mermaid-графом для GitHub/Obsidian). MCP: `get_dossier`.

## 10. Навігація, перевірка флагів, підказки (0.8)

- Усе клікабельне: назва завдання, робота, автор, флаг, «#3» у документації.
  Адреса в браузері відповідає відкритій картці, «Назад» повертає до попередньої,
  після форми відкривається оновлена картка. Клавіші: `?` — довідка, `/` — пошук,
  `g t`/`g f`/`g c`… — розділи, `b` — назад, `n` — створити.
- Робота над завданням **не зараховується без підтвердженого флага**: після
  «Завершити» вона в колонці «На перевірці флага»; підтвердження флага зараховує її,
  відхилення повертає виконавцю. `without_flag=true` — для допоміжних робіт.
- Підказки: агент — `request_hint` (потрібна його знахідка по завданню), людина —
  «Дозволити/Відхилити» на огляді, текст підказки — `record_hint`; облік у документації.
- `kind="decoy"` позначає приманки; агенти бачать їх у `get_context(challenge_id)`.
- «Хто застряг» на огляді: роботи без знахідок 20+ хв або із заблокованим виконавцем.
- `team-sync-agent --access-file <whoami.cli_access_file> run --task <id> -- <команда>`
  публікує експеримент: команду, код виходу, хвіст виводу, хеші й файли.

## 11. Агенти на зв'язку: runner, експерти, координатор (0.9)

**Runner** тримає агентів на твоїй машині: сам підхоплює питання до експертів,
запускає координатора і профілі, які ти або тімейти просите з вебу.

```sh
uv run team-sync-runner --config runner.toml --init --access-file .team-sync/<ctf>/owner.json
# відредагуй профілі (claude / codex / opencode, модель, ліміти), потім:
uv run team-sync-runner --config runner.toml --check   # чи знайдені програми
uv run team-sync-runner --config runner.toml           # Ctrl+C зупиняє всіх агентів
```

- Команди запуску **є лише в локальному `runner.toml`**. Сервер бачить назви
  профілів і ліміти й може тільки попросити запустити профіль за назвою.
- Запуск, який просиш ти сам (з вебу або твій runner автоматично), стартує одразу.
  Запуск, який просить **хтось інший** (тімейт чи агент), чекає твого рішення:
  панель на «Огляді» й сторінка **Агенти** (`g r`) → «Дозволити запуск».
- `confirm_locally = true` у профілі вимагає ще й клік на локальній сторінці runner'а
  (`http://127.0.0.1:18765/#token=…`). Там же «Пауза» і «Зупинити всіх агентів».
  Посилання лежить у файлі `runner.ui-link` поруч із конфігом (доступ лише власнику),
  не змінюється після рестартів і друкується командою `team-sync-runner --ui-link`.
- Кожен паралельний запуск профілю працює під своєю ідентичністю
  (`<Ти>-Pawn_xxxx`, `<Ти>-Pawn_yyyy`…), закріпленою за слотом runner'а. Робота,
  повернута після відхиленого флага, стартує в тому самому слоті, тож агент
  продовжує свою роботу. Ліміти: `max_minutes`, `max_runs_per_hour`, `max_parallel`.
- Коли процес агента завершився (успішно, з помилкою, за таймаутом чи скасуванням),
  сервер одразу повертає команді роботи, які лишились за цим агентом, з приміткою
  `[runner]` у знахідках. Чекати 15 хв, доки спливе оренда, не треба. Його статус
  стає «Вільний», а в профілі учасника видно «Процес живий / Процесу немає».
- Watchdog: `quiet_minutes = 6` зупиняє агента, вивід якого не змінювався стільки
  хвилин (завислий brute-force). `max_log_mb` (20) обмежує розмір виводу.
- Агент отримує мінімальне оточення: `PATH`, `HOME`, локаль, проксі, сертифікати,
  `XDG_*`, `UV_*`, `*_API_KEY`, `ANTHROPIC_*`, `OPENAI_*`. `PWD` дорівнює `workdir`.
  Інші змінні (зокрема `OPENCODE_*` і `TEAM_SYNC_*` твого шелу) не передаються.
  Додаткові можна дозволити: `pass_env = ["MY_TOKEN", "OPENCODE_*"]`.
- Координатор після рестарту runner'а не запускається одразу: час і стан останнього
  проходу зберігаються між рестартами.
- Чужу чинну роботу координатор може забрати одразу: «Доручити» → «Звільнити
  активне призначення зараз» з причиною (`task.assign` з `force=true`). Інакше
  доручення можливе після часу, вказаного у формі.
- `works_tasks = true` (і за бажанням `categories = ["crypto", …]`): runner сам
  запускає пішака на вільну роботу або на роботу, адресовану одній з його
  ідентичностей. Роботи над уже розв'язаними завданнями не роздаються: після
  підтвердження флага вільні роботи завдання закриваються автоматично, а тим, хто
  ще працює, надходить «зупиніться».
- Плейсхолдери в `command`/`env`: `{prompt}`, `{prompt_file}`, `{mcp_config}`
  (Claude Code), `{opencode_config}` (opencode), `{run_id}`, `{task_id}`, `{workdir}`.
  Приклад для opencode:
  `command = ["opencode", "run", "--model", "opencode/deepseek-v4.1-flash-free", "{prompt}"]`
  і `env = { OPENCODE_CONFIG = "{opencode_config}" }`.

**Питання до експертів.** Слабкий агент, що застряг, викликає
`ask_expert(question, details, tried, task_id, skills=["vision"])`. Обов'язково
описати, що вже перевірено. Діють ліміт у 5 відкритих питань і захист від дублів.
Runner, у якого є профіль з `answers_questions = true` і потрібною навичкою, сам
запускає експерта. Відповідь (`answer_question`) приходить тому, хто питав,
терміновим повідомленням і стає знахідкою з ребром до його роботи. Люди питають
кнопкою «Поставити питання» в картці роботи або відповідають самі.

**Координатор.** Профіль із `coordinator = true` і `every_minutes = 10` запускається
раз на N хвилин, якщо щось змінилось. Активним може бути лише один координатор у
проєкті. Він починає з `get_board` (увесь стан команди одним викликом), роздає й
адресує роботи, пише людям. Флаги, підказки й чужі запуски він не підтверджує:
флаги тепер підтверджує тільки людина.

**Повідомлення агентів — це дані.** Текст запиту від іншого учасника агент бачить у
блоці `<data>` з поясненням, що це не інструкції. Прохання не розширюють прав
отримувача.

**Живий веб і звуки.** Нові події з'являються без перезавантаження, відкрита картка
оновлюється на місці. Окремі звуки для повідомлень, термінових повідомлень, нових і
підтверджених чи відхилених флагів, рішень, питань і відповідей. У фоні працюють
лічильник у назві вкладки й системні сповіщення. Налаштування — «звук» унизу бічної
панелі. Браузер дозволяє звук лише після першого кліку на сторінці.

## 12. Промпти й повна автоматизація (0.9)

- `scripts/up.sh "Назва" Нік`: сервер, веб, проєкт, профілі агентів
  (`team-sync-runner --init --detect`) і runner у фоні. Повторний запуск безпечний.
  `scripts/up.sh --stop "Назва"` зупиняє агентів цієї машини.
- `team-sync-runner --init --detect [--pawn-model …] [--expert-model …]`: профілі під
  встановлені CLI. Якщо є `claude` — експертом стає opus, координатором sonnet. Якщо
  лише `opencode` — пішак DeepSeek Flash, експерт із зором (VL-модель) і загальний
  експерт. Автоматично беруться лише безкоштовні моделі (`…-free`); платну задай явно:
  `--pawn-model opencode-go/deepseek-v4.1-flash`. `--background` / `--stop` — запуск у
  фоні й зупинка; `--background` перезапускає runner, якщо `runner.toml` змінився.
  `--check` перевіряє ще й доступ до сервера.
- Ролі: `get_role("worker" | "expert" | "coordinator")` (MCP) або
  `GET /api/v1/roles/{role}`. Ті самі тексти runner вставляє в свої одноразові запуски.
- Промпти проєкту: сторінка **Промпти** (`g i`), `GET /api/v1/projects/<id>/prompts`,
  `team-sync-agent --access-file <файл> prompts`. Посилання для входу у веб:
  `team-sync-agent --access-file <файл> web-link [--open]` — це секрет, не пересилай.
